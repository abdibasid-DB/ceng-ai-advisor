# Source Collection Checklist

Use this checklist before adding any source to `knowledge_base/sources.json`.

## Reliability

- [ ] Is the source reliable?
- [ ] Is the author, institution, organization, or publisher trustworthy?
- [ ] Is the source transparent about where its information comes from?
- [ ] Is the information factual rather than unsupported opinion?

## Relevance

- [ ] Is the source relevant to Computer Engineering?
- [ ] Does it help answer prospective student questions?
- [ ] Does it match one or more knowledge-base categories?
- [ ] Does it add useful information that is not already covered well?

## Recency

- [ ] Is the source recent enough for its topic?
- [ ] Is the publication date or last-updated date known?
- [ ] For AI, cybersecurity, employment, salaries, and technology trends, is it preferably from the last three to four years?
- [ ] If the source is older, is the information still stable and useful?

## Duplication

- [ ] Does this source duplicate another source already collected?
- [ ] If it overlaps with another source, is it more official, more recent, or more detailed?
- [ ] Have duplicate sections or repeated content been noted for later preprocessing?

## Source Tracking

- [ ] Is the title saved?
- [ ] Is the source name saved?
- [ ] Is the source type assigned?
- [ ] Is the URL saved, if it is a web source?
- [ ] Is the publication date saved, if known?
- [ ] Is the date accessed saved?
- [ ] Is the category assigned?
- [ ] Is the language recorded?
- [ ] Is a reliability note written?
- [ ] Is the raw file path saved, if a local copy exists?
- [ ] Are any useful notes added?

## Final Decision

- [ ] Should this source be included in the knowledge base?
- [ ] If included, is it ready to be stored in `knowledge_base/raw/` during the collection stage?
- [ ] If rejected, has the reason been recorded elsewhere if needed?
